# Live Cheats / Meath00k

When the game is running, **Enable Cheats / Meath00k** enables console cheats and loads the bundled mod together with one click. The button then offers **Disable Cheats / Meath00k**, which restores changed cvars, restores the mod's game patches and makes its registered commands inactive. There is no context menu. The button is disabled while switching, and repeated clicks during that operation are ignored. The game stays open throughout.

When the game is closed, the existing install/uninstall action for the startup proxy remains available. A verified bundled startup proxy already loaded by the game can also be adopted by live control. Disabling a session does not remove the installed proxy from disk; uninstall it with the game closed if it should not load on the next launch.

## Cvar display and restoration

During an active cheat session, the native HUD shows newly changed protected cvars whose values differ from the engine's own reset values. Enabled `noclip`, `notarget` and `god` states appear at the beginning of the same list as `name = ON` and disappear individually when switched off. These commands read actual reflected player bitfields, independently of cvar filtering and console input history.

The list is attached below the DESRU modifiers in the top-right FPS/version/modes block and flows downward. Its scale is 0.65, below the existing OSD text scale, and is independent of the speedometers. Position and spacing follow the game's current font metrics, viewport and minimal/full OSD mode (10 virtual units of right margin, the metrics formatter's glyphHeight+2 row advance, and space below the final modifier line). Turning off the DESRU OSD also hides the list. Long lists continue in columns to the left and shrink further if needed. Cvars refresh every 500 ms; command flags are read in the normal display tick. The list hides in menus/loading and when the game loses focus, and supports up to 512 rows with bounded text per row. It uses the game HUD, including exclusive fullscreen.

All names already nondefault in the initial snapshot are excluded from the cvar portion, including preserved gamma, audio, weapon preferences and build information, even if changed again later. With cheats disabled the list is empty.

Protection is derived from the engine's flags: CVAR_CHEAT, excluding CVAR_NOCHEAT, ROM, INIT and SHIPPINGDISABLED. Reading and restoration still include the full protected set; the HUD filter only affects display. It uses the session snapshot rather than an arbitrary list of cvar prefixes.

Before enabling the combined mode, DESRU saves the initial protected cvar values. Disabling restores only values changed during that session. Values initially at their engine defaults return to defaults; existing custom preferences return to their original values. Unchanged custom preferences are left alone. For an already running startup proxy first seen by DESRU, the baseline begins when DESRU attaches; earlier settings cannot be inferred. The snapshot survives restarting DESRU while the same game process continues. Disabling also clears the current player's noclip, notarget and god state through game property setters.

## Implementation and limits

Native attachment waits for the command registry, AddCommand function and usable game font metrics. Starting DESRU before the game no longer permanently selects the desktop overlay after the first empty startup pointer. Transient failures retry with a delay capped at two seconds; while waiting, the external overlay stays hidden. Unsupported layouts or conflicting hooks retain the existing fallback without overwriting unknown code. A new game process resets the retry state. Speedometer glyph measurements also refresh from the game as fonts initialize or change.

- `ProtectedCvarMonitor` reads cvar metadata, names, reset strings and live values. Boolean and float formatting differences do not produce false changes.
- `PlayerCheatMonitor` reads the byte offsets/masks decoded from reflected `idPlayer.noClip`, `noTarget` and `godMode` bool getters. Unknown getter code is rejected; no fixed player offsets are assumed across versions. There are no new game hooks or game-thread calls for state polling. These indicators do not enter the cvar baseline or restoration list.
- `CheatCvarSession` persists a JSON baseline in game-owned session storage (`DESRUB01`) and verifies restoration before locking the console again. Strings restore through the native `idCVarSystem::SetCVarString`, avoiding console quoting problems.
- `NativeHudExtension` uses a separate executable callback and double-buffered row storage (`DESRUE01`). A serialized mailbox runs native calls on the HUD thread. Its callback is linked from DESRUS08 at shared-state offset 1016. Earlier speedometer commands and low-health hooks are preserved.
- `LiveMeathook` requires the exact bundled DLL SHA256 `02c7159964245e249bcffc12598651b871f6c73925c4e04355510587114cdab3`. It prepares a private late-entry copy, preserving CRT initialization while bypassing startup-only hooks and the game's startup initializer. The original bundled DLL and game executable stay unchanged.
- Switching restores upstream undo records, the main-loop callback, the unrecorded filesystem detour and registered command handlers. It validates expected bytes and suspends the process briefly while applying or restoring patches, rolling back on mismatch. Code and the DLL stay allocated until the game exits so an in-flight callback cannot reach freed memory. Disabled handlers are inert. Session state (`DESRUMH1`) allows DESRU to reconnect to the same game.
- Adaptive metadata resolution covers cvars and the three player cheat setters on 1.0, 1.1 and Steam 6.66 Rev 3.2. Live mod switching has been exercised on 1.1; startup-proxy adoption and other game versions have not received the same live regression coverage.
